02

Enter download mode

The installer usually resets the board for you. If the port won’t connect, put it in download mode by hand.

    03

    Build a flashable image

    The hub is a pure ESP-IDF build (four parts); the C3 node is an Arduino/PlatformIO build (merge into one factory image); the ESP8266 is a single image. Each block below prints the exact commands and offsets the hosted manifests use.

    Native-USB boards: enable ARDUINO_USB_CDC_ON_BOOT=1 (PlatformIO) on the C3 so serial logs come over the same cable you flash with.
    04

    Flash

    1. Use a data cable. Charge-only USB-C cables show no port.
    2. Open this page in Chrome or Edge on a computer, over HTTPS or localhost.
    3. Select the board and firmware in the card at the top, then press Connect & install.
    4. Pick the serial port in the browser prompt. Keep Erase device ticked on a first install.
    5. Wait for “Installation complete”, then unplug and replug, or tap RST.
    Only one program can hold the port. Close any serial monitor (Arduino, PlatformIO, PuTTY) before flashing.
    05

    Wire a node

    Every node switches one actuator (solenoid gate, auger or pump via a 5 V relay), keeps its own DS3231 RTC on I²C, and measures its 12 V supply so the hub can show voltage. Pick your MCU for the pin map — the same table lives in PLAN.md §4.4/§4.5.

    FunctionGPIOBoard labelDirConnects to
    Default-OFF is hardware, not firmware (SR1): during boot the GPIOs float — an active-low relay module can click on. Pull the relay input to its OFF level with ~10 kΩ (pull-up for active-low, pull-down for active-high), and put the solenoid on the NO contact.
    Before power-up: tie every ground together (MCU, relay, 12 V supply, load), add a flyback diode (1N4007) across a bare solenoid, and check the ADC divider output with a meter before the first boot.
    06

    Pair a node with the hub

    1. Power the hub and finish the setup wizard (time zone, Wi-Fi — the nodes follow the hub’s channel).
    2. On the hub: Settings → Wizard / Add node. The hub opens a 60-second pairing window.
    3. Power the node while it is unpaired — it beacons and appears in the hub’s discovery list with its signal.
    4. Compare the 4-digit code the hub shows with the one the node prints over serial, confirm on both, then fill the form (name, mechanism, hopper size, amount in it now).
    5. Calibrate on the node page (test runs + weighed amounts), then set a schedule.
    The node’s per-feed, hourly and daily caps are enforced on the node itself — the hub is advisory, so a lost link never means runaway feeding (§3.3).
    Troubleshooting

    When the port won’t show up.

    Most failures are a cable, a driver, or a program already holding the port.

    No serial port appears in the browser prompt
    Swap to a known data cable and a different USB port. On ESP32 / ESP8266 boards with a USB-UART bridge, install the CH340 / CP210x driver. The hub and the C3 enumerate natively — if they don’t, they are in a user firmware that crashed the USB stack: enter download mode by hand (chapter 02).
    “Failed to connect to ESP” or a timeout
    Hold BOOT, tap RST, release BOOT, then retry. Close any serial monitor first — only one program can hold the port.
    The hosted build says firmware is missing
    The Pages site serves the latest CI release. If a target shows “not found”, the release workflow may still be running — check the releases page, or flash a local build with My own .bin.
    Flashed, but the hub screen stays black
    The panel bring-up is logged on serial — look for aio-display: panel 800x480. A backlit-but-black screen is a timing/pin-map mismatch (constants in hub/main/display_hw.cpp); a dead-dark screen is the backlight (CH422G EXIO2). The hub keeps running headless either way — feeding never depends on the display.
    The C3 reboots in a loop after flashing
    Usually an app-only image written at 0x0 instead of 0x10000, or a merged image missing the bootloader. Prefer the hosted build, or re-merge with the command from chapter 03.
    Does anything leave my computer?
    No. Hosted builds come straight from this site to the board over Web Serial; a file you pick is read locally and never uploaded. See ESP Web Tools.
